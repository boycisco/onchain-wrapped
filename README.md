# Onchain Wrapped

A backend for **Onchain Wrapped** - a Spotify-Wrapped-style report for a
Base wallet. Enter an address, get a personalized snapshot of your onchain
activity: real statistics, a behavioral profile, a personality name, and a
short roast.

The report is powered by **verified structured statistics**. Nothing in the
numbers is generated by a language model. The LLM is used only to write
prose, and it is optional: a deterministic fallback always works.

## What it is

- A **backend** and analysis engine. A frontend will be integrated later.
- A **deterministic pipeline**: wallet -> fetch -> normalize -> analyze ->
  identity -> roast -> Wrapped.
- An **honest analytics engine**. It does not fabricate USD valuations,
  success/fail counts it cannot prove, contract classifications it has not
  verified, or percentile claims it cannot support.

## What it is not

- Not a blockchain explorer.
- Not a general-purpose analytics dashboard.
- Not a finished product. It is an early, functional foundation.

## Stack

- **Node.js 22 LTS** + **TypeScript** (strict)
- **Next.js** (App Router), so a frontend can be integrated into the same app
- **Viem** for Base mainnet RPC
- **Alchemy** for indexed wallet history (via `alchemy_getAssetTransfers`)
- **Google Gemini** for the roast line only (optional)
- **Vitest** for tests
- **Zod** for input and env validation

No database is required for V1. Results are cached in-memory per process.

## Architecture (one paragraph)

Every wallet request flows through `runPipeline()` in `app/core/pipeline.ts`.
The data layer (`app/data/`) talks to Alchemy and Base RPC, normalizes
responses into our own models, and hides provider-specific shapes from
everything upstream. The analysis layer (`app/analysis/`) is a set of pure
functions over those models. The identity layer (`app/identity/`) turns
behavioral scores into a personality. The roast layer (`app/roast/`) writes
at most five lines of prose, with a deterministic fallback. The composition
layer (`app/core/wrapped.ts`) assembles a canonical `Wrapped` object, which
is what the API and (later) the frontend consume. See
`docs/architecture.md` for the full picture.

## Local setup

    git clone <your-fork>
    cd onchain-wrapped
    npm install
    cp .env.example .env.local
    # edit .env.local and set BASE_RPC_URL and ALCHEMY_API_KEY
    npm run dev

Open http://localhost:3000/api/health to confirm the server can reach Base.

## Environment variables

| Name | Required | Purpose |
|---|---|---|
| `BASE_RPC_URL` | yes | Base mainnet JSON-RPC URL. e.g. `https://mainnet.base.org` |
| `ALCHEMY_API_KEY` | yes for real data | Free at https://dashboard.alchemy.com |
| `GEMINI_API_KEY` | no | Roast generation. Falls back to templates if absent |
| `FORCE_ROAST_FALLBACK` | no | Set to `"1"` to always use template roasts |

See `.env.example` for the full template.

## Running tests

    npm test

Tests are deterministic and use fixtures. No live network calls in the
default suite. Provider integration tests mock `fetch`.

## API at a glance

    GET  /api/health                 -> { ok, chain, block }
    POST /api/wrapped  { wallet }    -> { wrapped, timings }
    POST /api/compare  { wallet, other } -> { a, b, comparison }

Full request/response documentation, error codes, and card shapes are in
`docs/api.md`.

Quick example (PowerShell):

    $body = '{"wallet":"0xd8dA6BF26964aF9D7eEd9e03E53415D37aA96045"}'
    Invoke-RestMethod -Method Post `
      -Uri http://localhost:3000/api/wrapped `
      -Body $body -ContentType 'application/json'

## Known limitations (V1)

- Base mainnet only.
- No USD valuation. We do not have historical price data and will not
  invent one.
- No verified contract classification. `uniqueAddresses`, not
  `uniqueContracts`.
- No transaction receipt enrichment. Almost all transactions have
  `status: "unknown"`. We never call an unverified transaction successful.
- No rarity percentile. `identity.rarity` is always `null`.
- UTC only, no timezone conversion.
- In-memory cache only. Swap for Redis by implementing `Cache` in
  `app/core/cache.ts`.
- Alchemy is the only indexer implementation. Adding another is documented
  and contained to `app/data/`.

## Frontend status

This repository currently ships a **placeholder** Next.js landing page. A
separate frontend agent will build the real UI, which will then be integrated
into this repository. The backend is designed so the frontend can be built
entirely against `docs/api.md` without reading any backend internals.
